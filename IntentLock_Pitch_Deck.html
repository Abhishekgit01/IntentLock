🏛️ Smart Contract Guard Hook

IntentLock implements a native Safe BaseGuard attaching to Safe 1.4.1. Safe execution triggers:

safe.execTransaction(...)
  ↳ guard.checkTransaction(...)
    ↳ registry.consumeAttestation(...)

4 Immutable Guard Rules:
1. operation != 1 (Unconditional DELEGATECALL revert).
2. Nonce must equal safe.nonce() - 1 (Anti-frontrunning).
3. safeTxHash must match Registry attested digest.
4. Attestation must not be consumed or expired.

🛡️ Decentralized Verifier Quorum

Three independent off-chain verifiers run in isolated environments (e.g. AWS, GCP, Bare-Metal):

  • Zero Trust on UI: Verifiers read raw calldata from RPC, ignoring UI labels.
  • Bytecode Hash Pinning: Verifies target contract code hash matches allowlist.
  • EIP-712 Signatures: Each verifier signs AttestationRecord with isolated private keys.
  • 2-of-3 Threshold: Registry enforces validSigners >= 2 before storing attestation.

🏆 The 4 Pillars of IntentLock's Unfair Advantage

1. The Enforcement Gap Is Closed

All competitors operate at the advisory layer (warning popups, extension banners). When attackers use DNS spoofing, compromised frontends, or urgency social engineering, humans click approve. IntentLock moves the security enforcement inside the smart contract itself.

2. Bytecode Pinning vs. Fragile Simulation

Simulation engines execute transactions speculatively. Modern attack contracts inspect gasleft() or block variables to behave innocently in simulation, then execute malicious logic in real blocks. IntentLock verifies exact runtime bytecode hashes deterministically.

3. Non-Invasive Safe 1.4.1 Native

IntentLock does not require migrating funds to a new, unproven smart account. It connects seamlessly to existing Safe 1.4.1 deployments as an authorized BaseGuard, preserving existing key structures and signer workflows.

4. Cryptographic Nonce & Replay Protection

Attestations cannot be front-run, reused across chains, or held for later malicious execution. Each attestation is bound to safeNonce - 1, block.chainid, and marked consumed atomically in the registry during execution.
